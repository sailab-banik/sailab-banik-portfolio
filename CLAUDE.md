## Project state

Single-page portfolio for Sailab Banik, built and live. `src/app/page.tsx` composes `Header`, `Hero`, `Experience`, `Work`, `Writing`, `Credentials`, `About`, and `Footer` from `src/components/`.

## Stack notes that differ from older Next.js/Tailwind

- **Next.js 16 App Router.** All routes live under `src/app/`. Read the version's own docs in `node_modules/next/dist/docs/` (see AGENTS.md) before using an API from memory.
- **Route component props are globally generated types**, not hand-written. Use `PageProps<"/some/route">` and `LayoutProps<"/some/route">` — declared in `.next/types/routes.d.ts`, regenerated by `next dev`/`next build`. `params` and `searchParams` on them are Promises and must be awaited. After adding a route, run dev or build so the types pick it up; TS errors about an unknown route string usually mean stale generated types.
- **Dev artifacts go to `.next/dev/`**, production ones to `.next/`. Both are gitignored.
- **Tailwind CSS v4** — there is no `tailwind.config.*`. Configuration is CSS-first: `@import "tailwindcss"` plus the `@theme inline` block in `src/app/globals.css`. **Any token a media query needs to override must be a raw custom property on `:root` that `@theme inline` merely references** (`--color-ink: var(--ink)`, `--text-display: var(--display-size)`). `@theme inline` inlines a literal value into the utility it generates, so overriding that token later changes a variable nothing reads — the override silently does nothing. This has bitten the palette (dark mode) and the type scale (the display size below `md`); assume it applies to every token, not just colour.
- **Fonts** are Bricolage Grotesque (`font-sans`, loaded with the `opsz` and `wdth` axes) and Newsreader (`font-serif`), via `next/font/google` in the root layout and mapped through `@theme inline`; `body` carries `font-sans`. The hero name alone is set in Instrument Serif (single weight 400), exposed as `--font-instrument` and applied by `.type-display` in `globals.css` rather than through a Tailwind utility. Newsreader is loaded without an italic style, so the `italic` utility silently falls back to roman — add `style: ["normal", "italic"]` to the loader before using it.
- **The favicon is `src/app/icon.png`**, via the Next.js file convention — there is no `public/favicon.ico`. The share card is generated the same way, by `src/app/opengraph-image.tsx` with `next/og` — there is no `og.png`. `next/og` rasterises with satori, which needs *static* font files, so it reads Instrument Serif and Bricolage Medium from `assets/fonts/` with `node:fs`; the variable font `next/font/google` loads for the page cannot be reused there.
- **Dark mode** is `prefers-color-scheme` only: a media query in `globals.css` redefines the palette custom properties. There is no class toggle, no theme switcher, and no `dark:` utilities anywhere — components use the semantic tokens and both themes follow.

## Conventions

- Import from `src/` via the `@/*` alias (`@/components/...`), configured in `tsconfig.json`. Content JSON sits outside `src/` and is imported relatively from `src/lib/content.ts`.
- Component files are kebab-case and export a named component: `social-links.tsx` exports `SocialLinks`.
- TypeScript is `strict`; the ESLint config is `next/core-web-vitals` + `next/typescript`.
- `AGENTS.md` is regenerated by `next dev`. If it shows up dirty in `git status`, commit it with the work rather than reverting it.

## Code style

- Architecture-driven: decide structure first, then write. Prefer small,
  single-purpose modules over large files.
- Minimal comments. Code should read without them; comment only non-obvious
  decisions.
- No defensive programming. No speculative null checks, try/catch, or
  fallbacks for cases that can't occur.
- No emojis anywhere — code, UI copy, commit messages, docs.
- READMEs and docs stay concise. No marketing tone, no filler sections.

## Content

All copy, project data, and links live in `content/*.json` — `profile.json`, `experience.json`, `projects.json`, `articles.json`, `certificates.json`, `sections.json`, `stack.json` — loaded through typed helpers in `src/lib/content.ts`. Components never hardcode text. That includes section headings and their one-line leads: `sections.json` is keyed by section id and read by `Section` in `src/components/section.tsx`.

That extends to styling hooks: `profile.emphasis` names the substring of `statement` the hero sets in the sans face, so the emphasis follows the copy instead of being markup in a component. `sections.json` holds each section's rail heading and its lead line; the leads are first-person and say something about the work, not captions describing the page.

`--display-size` is derived, not chosen: `Sailab Banik` advances 4.042em in Instrument Serif with `-0.02em` tracking, and the content column is `100vw - 80px` until it caps at 1160px, so `24.49vw - 1.224rem` (capped at `17.76rem`) is the size at which the name spans the column. A media query re-solves it as `24.49vw - 0.735rem` below `md`, where the gutter is 24px instead of 40px. Both carry about 1% slack against font-rendering variance. Change the name, the font, or the tracking and every coefficient has to be re-measured or the hero stops fitting. Measure the *text*, not the block: the line is a block element that fills the column whether or not the type does, so `getBoundingClientRect()` on it always reports a perfect fit. Use a `Range` over its contents.

## Images

`public/images/profile_picture.png` is the untouched original headshot and the source for every derived asset — `public/images/portrait-cutout.png` (hero) and `src/app/icon.png` (circular favicon). Regenerate from it rather than editing it.

The hero portrait is a background-removed cut-out with the shoulder fade baked into its alpha, so it needs no frame and no CSS mask. The subject was segmented on-device with Vision's `VNGenerateForegroundInstanceMaskRequest` from a Swift script (`swift cutout.swift <in> <out>`, no Xcode project needed), then cropped and alpha-ramped with sharp. Against the dark ground the black polo would merge into the page, so `.portrait` carries a `drop-shadow` rim in dark mode only.

Everything under `public/` is served verbatim at its own URL, so a file there is public the moment it is committed, whether or not anything links to it. Check what a scan or document carries before adding it — the certificates under `public/certificates/` were confirmed with Sailab as already public.

`sharp` is available as a Next.js dependency. From a script in the repo root:

```js
import { createRequire } from "node:module";
const sharp = createRequire(import.meta.url)("sharp");
```

A bare `import sharp` fails: the package is CommonJS, and Node resolves bare specifiers from the importing file's own directory, so a script written outside the repo cannot find it.

Replacing an image in place does not invalidate the Next.js image optimizer cache, which is keyed on the request URL — the old rendition keeps being served in dev. After overwriting a file under `public/`, `rm -rf .next/cache/images` and restart, or the page will show the previous version.

## Checking the UI

- **Narrow widths.** Resizing the browser window will not go below roughly 1000px. Load the page in same-origin iframes at the target widths instead.
- **The other theme.** Set the palette custom properties on `document.documentElement.style` — an inline style outranks the `prefers-color-scheme` rule. This triggers a hydration warning in the dev overlay, which is the injection rather than a bug, and `transition-*` classes animate the swap, so wait before screenshotting.

## Deployment

Vercel handles deploys: push to `main` is production, PRs get previews.
GitHub Actions runs CI only (lint, typecheck, build) — never deploys.

In `.github/workflows/ci.yml`, `next build` must run **before** `npx tsc --noEmit`: `LayoutProps` and `PageProps` are generated into the gitignored `.next/types`, so a standalone typecheck on a clean checkout cannot resolve them.
